# Domain Docs

This repository uses the single-context layout for domain documentation.

## Before exploring

- Read `GLOSSARY.md` at the repository root when it exists.
- Read relevant decisions under `docs/adr/` when they exist.

If these files do not exist, proceed without treating their absence as a problem. Create them lazily when domain terms or architectural decisions are actually resolved.

## Vocabulary

Use terms defined in `GLOSSARY.md` in issue titles, refactor proposals, hypotheses, and test names. If a required concept is not defined, consider whether the glossary needs to be extended.

## ADR conflicts

If a proposed change contradicts an existing ADR, call out the conflict explicitly instead of silently overriding it.
