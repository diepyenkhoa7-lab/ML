## Public dictionary contracts

`MarketService().normalize_locations(raw: str | None)` returns exactly:

| Key | Type and meaning |
| --- | --- |
| locations | list[str], distinct labels in first-observed order |
| location_status | normalized when all tokens match, review when any remain unresolved, missing for None/blank |
| location_aliases | dict[str, str], original trimmed token to label; retains accents, case and (mới) evidence |
| location_unresolved | list[str], unrecognized tokens, never inferred from a substring |
| work_modes | list, always empty in T05 |
| location_reason | str, matching/review/missing explanation and (mới) scope note where applicable |

The caller keeps the original whole field; location_report does this as
`location_raw` without alteration. Whitespace surrounding split tokens is ignored
for recognition. HCM, TP.HCM, ho chi minh, Hồ Chí Minh map to HCM; HN, Ha Noi,
Hà Nội map to HN, case-insensitively. A terminal ` (mới)` may accompany these
aliases, but remains in alias evidence and the whole raw field. Other province
labels match the explicit, exact catalogue observed in the new source location
fields, including source spellings Dak Lak and Thừa Thiên- Huế. Their (mới)
variants remain distinct source labels. This catalogue is not an address parser
or a current administrative-boundary register.

Only actual `|` and `&` separators are recognized here. Unknown addresses,
Điện Biên Phủ, regional/foreign labels outside this province catalogue, and
`2 nơi khác`/similar placeholders stay review. The exact source province label
Điện Biên can be retained; a street containing that phrase cannot match it.
Normalization does not establish province comparability across years. No Remote
classification or multi-location/unique-job counting semantics are implemented;
these remain T06, awaiting a separate signal.

`MarketService().location_report(source_id, *, location=None, status=None)` verifies
the source via preview(limit=None) and returns a plain dictionary:

- source_id: str; raw_row_count: int, the full source's raw rows before filters.
- location_options: sorted list[str] from the full source's recognized labels.
- alias_table: list[dict], one whole raw location string per entry with its six
  normalization fields and raw_rows frequency. Filters apply to both tables.
- rows: list[dict], one source row per entry, retaining source_id, job_id (empty
  when absent), original job_url, location_raw and all normalization fields.
- csv: str, the same filtered rows with a header even when no rows match.

Report list/dict fields are JSON strings so tables and CSV retain unambiguous
arrays and token evidence. Canonical location filtering uses list membership;
status filtering uses exact status. None means no filter. Source errors remain
MarketError. The page encodes the CSV as UTF-8 with BOM for Vietnamese text.
Frequencies describe raw rows, not deduplicated postings or market demand.

Example callable from a CLI without installing the checkout:

```sh
PYTHONPATH=src /private/tmp/ml-market-env-20261029/bin/python - <<'PY'
from career_market import MarketService
service = MarketService()
print(service.normalize_locations('Hồ Chí Minh (mới)'))
print(service.location_report('jobs-2026', location='HCM', status='review')['csv'])
PY
```
